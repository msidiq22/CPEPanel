四、真机实测的协议契约（重要，与网页版前端不一致处已标注）

这些是真机上逐条打出来的返回值，不是从文档或前端代码推断的。写接口的返回值语义是本轮最大的坑。

接口真机实测契约
zwrt_wms
zte_libwms_send_sms		 参数 {number, sms_time, message_body, id, encode_type}
· 成功返回 {"result":3}，失败（如号码为空）返回 {"result":2}
· id 必须是字符串 "-1"，传数字 0 直接报 status 2
· 缺 id 或 encode_type → status 2（参数非法）
· message_body 为正文的 UTF-16BE 大写十六进制
zwrt_wms
zwrt_wms_delete_sms		 参数 {"id":"3;5;9;"} —— 分号连接且末尾必须带分号；缺末尾分号同样返回 {"result":2}。成功 {"result":3}。
zwrt_wms
zwrt_wms_get_cmd_status		 参数 {"sms_cmd":N}（1=就绪检测、4=发送、5=存草稿、6=删除），返回 sms_cmd_status_result：3=成功、2=失败、其它=进行中。注意：该值在设备空闲时也会残留为 3，所以只能作为「写请求已被受理」的辅助确认，不能单独当成功依据。
zwrt_zte_mdm.api
sim_switch_slot		 参数 {"slot":1|2}。受理时响应体是空的（连 result 字段都没有），只有参数非法才抛 status 2。因此判定只能用「没抛异常 = 已受理」，真实结果必须回读 get_sim_info_before.current_sim_slot。
zwrt_zms
zte_libwms_get_sms_data
对象名易错		 ubus 对象名是 zwrt_wms（不是 zte_libwms，后者返回 -32000 Object not found）。
参数 {page:0, data_per_page:500, mem_store:1, tags:10, order_by:"order by id desc"}
返回数组键为 messages；单条字段为 id / number / content / date / tag / mem_store / draft_group_id
· content 是 UTF-16BE 十六进制
· 时间是 date（tags 传 0 会返回空列表）
· tag：0=已读收到 1=未读收到 2=已发送 3=发送失败 4=草稿

五、真机测试中发现并修复的 3 个缺陷

致命缺陷 1：写操作成功判定错误 —— 发送成功却提示失败

代码里原本按网页版前端的写法判断 result == "success"，但真机返回的是数字 {"result":3}。结果是：短信实际已经发出，App 却提示「设备未接受发送请求」。SIM 切换更严重 —— 它返回空响应体，判定必然为假。

修复：新增统一的判定函数 J.writeAccepted()，同时兼容 3 / "3" / "0" / "success" 为成功，2 / -1 为失败，响应体为空返回「无结论」；SIM 切换则改为「未抛异常即受理 + 回读真实卡槽确认」。

阻断缺陷 2：SmsCodec.kt 缺少闭合大括号，工程无法编译

上一轮生成 SmsCodec.kt 时 object 声明少了一个 }。上一轮的编译任务在 PowerShell 层面显示 exit 0，但 Kotlin 编译器实际报错，容易误判为成功。

修复：补齐括号；同时修正生成脚本 gen_smscodec.py，避免下次重新生成时再次引入该问题。本轮编译 compileDebugKotlin 通过，BUILD SUCCESSFUL。

体验缺陷 3：新建短信页键盘弹出后「发送」按钮不可达

该页面用的是不可滚动的 Column，软键盘一弹出就把底部的「发送」按钮整个顶出屏幕，用户根本点不到 —— 功能形同不可用。这个问题只有在真机上点过一次才会暴露。

修复：内容区加 verticalScroll + imePadding。修复后键盘弹起时字数统计、编码预览、发送按钮均可正常访问与点击。
